# Modding reference

Every key each file a mod can change is read with: its type, what the game takes when it is absent, and its limits. Generated by `mw3 --reference docs/modding-reference.md` from `src/upgrades/reference/`; do not edit it by hand. A test runs the game's readers over its own files and fails when a reader reads a key this list lacks or the list names one no reader reads, so it follows the code. How mods work: `docs/modding.md`.

## mod.txt

- Where: the mod folder's root (`mods\<mod>\mod.txt`)
- Read by: ours: `mech3::mod_parse`, `mech_row_parse`, `weapon_row_parse`

`key=value` lines, the key in any case, spaces around either trimmed; `#` starts a comment line. An unknown key is ignored (a newer mod still loads). `world`, `ia_world`, `mech`, `weapon` and `campaign` may repeat. The values of `mech=` and `weapon=` are a name and then `key=value` words; there an unknown key refuses the line.

| Key | In | Type | When absent | Limits | What it does |
|---|---|---|---|---|---|
| `name` | top | text | required | - | The mod's name, shown on the MODS screen. Without it the mod cannot be used. |
| `version` | top | text | none | - | Shown beside the name; EXPORT puts it in the zip's name. |
| `author` | top | text | none | - | Shown in DETAILS. |
| `for` | top | text: `mw3` or `mw3pm`, a version may follow | either game | the first word, any case | Which game the mod is for; MechWarrior 3 leaves out a `mw3pm` mod, Pirate's Moon a `mw3` one. |
| `description` | top | text | none | - | A line about the mod. |
| `world` | top | a folder's name | none | - | A new world: its files in `zbd\<folder>\`, its `<folder>.gs`. |
| `ia_world` | top | `<folder> <name>` | none | - | Puts a world on Instant Action's list under the name given. |
| `mech` | top | `NAME tech=… mass=… class=… [model=…] [title=…]` | none | - | A new mech, numbered after the game's own; its definition is `dfn_NAME.zrd`. |
| `tech` | mech= | `clan`, `sphere` or `any` | required | - | Which side may field it. |
| `mass` | mech= | int (tons) | required | 10 to 100, in steps of 5 | Its tonnage. |
| `class` | mech= | `light`, `medium`, `heavy` or `assault` | required | - | Its weight class. |
| `model` | mech= | a mech's name | NAME | - | The mech whose models, motions and sounds it uses. |
| `title` | mech= | text, the rest of the line | NAME | - | The name shown; last on the line. |
| `weapon` | top | `NAME ammo=… tech=… [title=…]` | none | - | A new weapon, numbered after the game's own; its definition is weapons.zrd's of that name. |
| `ammo` | weapon= | `yes` or `no` | required | - | Whether it takes ammunition. |
| `tech` | weapon= | `clan`, `sphere`, `any` or `none` | required | - | Which side's mech lab offers it. |
| `title` | weapon= | text, the rest of the line | NAME | - | The name shown; last on the line. |
| `campaign` | top | a file in the mod | none | inside the mod's folder | A custom campaign's file (the next section). |

## A custom campaign's file

- Where: the mod, named by mod.txt's `campaign=`
- Read by: ours: `mech3::campaign_parse`

`key=value` lines as mod.txt's (a UTF-8 mark at the start allowed). Unlike mod.txt, an unknown key or a line without `=` refuses the campaign whole, its line named. `op=` and `mission=` repeat, in play order; every `op=` needs a `mission=` after it.

| Key | In | Type | When absent | Limits | What it does |
|---|---|---|---|---|---|
| `name` | top | text | required | once | The campaign's name on the MODS screen. |
| `stock` | top | `default` | default | only `default` for now | The mechs and stock a new campaign starts with. |
| `movie_start` | top | fmv.zrd's name, one word | none | once | Played before the first briefing. |
| `movie_end` | top | fmv.zrd's name, one word | none | once | Played when the last mission is won. |
| `op` | top | `<heading> [bases=N]` | none | bases 0 to 3 | An operation's heading for the missions after it; `bases=` resets the field bases at its first mission. |
| `mission` | top | `<world> <number> [briefing] [movie] [bases=N]` | required (one at least) | number 1 to 99; 99 lines at most; `-` for no briefing or movie; bases 0 to 3 | A mission: the world's folder and its `m<number>` block, then the briefing and movie by name. |

## weapons.zrd

- Where: `zbd\reader.zbd` (or the mod's own reader entry)
- Read by: `zwep::init` 0x00583880, `read_effect` 0x00584bb0; `mech3::WeaponType` 0x004af4f0

A reader file: `KEY value` pairs and `( ... )` lists. Keys match exactly, case included. `BALLISTICS` holds one `NAME ( ... )` record a weapon (the name is how `dfn_*.zrd` and mod.txt's `weapon=` name it). A key the game does not know is never looked at. A flag (`flag 0/1`) left out keeps the weapon's default (off unless said). `IMPACT` holds an effect block per soil name the world knows (the first, the default, also for any soil without its own).

## dfn_<mech>.zrd (a mech's definition)

- Where: `zbd\reader.zbd`, `dfn_<mech>.zrd` (a mod's new mech: mod.txt's `mech=`)
- Read by: `mech3::read_dfn` 0x0046ba40 and its blocks; the cameras 0x004215d0; the gaits and canned effects 0x00431a70

## aiv.zrd (a mission's vehicles)

- Where: each world's reader archive

## Script commands (interp.zbd, a world's .gs and .gw)

- Where: `zbd\interp.zbd` (a mod's own scripts)
- Read by: the preprocessor 0x00590e80, the dispatcher 0x00591300 (`zint::dispatch`), MW3's pre hook 0x004107e0

One command a line, its words split by spaces; `$name` expands a macro (`set`). The type is the arguments in the order the command reads them: `s` text, `f` a number with a point, `i` a whole number, `b` on/off (`on` or `true`, anything else off), `-` none.
