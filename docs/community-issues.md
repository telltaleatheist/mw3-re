# What broke for players

A watch-list from the community's reports and unofficial fixes (web search,
2026-10-20, Owen: "knowing what broke for people could point us toward
problems that we'll almost certainly encounter too"). Anecdotes, not
confirmed bugs; each is checked against the port when its code is reached.

| Report | Where | What the port says so far |
|---|---|---|
| Physics and "rubberbanding" go wrong on fast machines; players cap at 60 fps | VOGONS, a WineD3D + ImageCFG recipe | Matches the per-frame steps found in the port (falls, slopes, jets, blend-in, lava, smoke): all now per 1/30 s (`fixes.md`, Frame rate) |
| Frequent crashes when hitting mechs (2016, d3d mode) | VOGONS | Open; the crater clipper's freed-buffer reads past 128 entries and its fixed side tables (`craters.md`, fixed in the port) are candidates for misses that crater the ground. Damage and the hit path are ported with crash fixes (equipment critical's float bits, `fixes.md`); check the rest of the hit path when weapons' second half lands |
| Crash when the mech overheats or on an alpha strike (Windows XP) | MajorGeeks compatibility DB | Open. Heat and power are ported; an overheat shuts down through 0x41cc30. Look at what the shutdown and alpha fire reach that the port has not (HUD, sound, the weapon manager's fire-all) |
| Display freezes when cresting hills or riverbanks | MajorGeeks | Open; possibly the ground probes (`movement-ground.md`: the never-written probe width, now a fix) or the renderer's clipping. Also a candidate: the crater clipper's walk (0x510da0) loops forever, freezing the game, when a terrain polygon's corner lies on a crater's outline to within a float's error (`craters.md`; 3 to 10 in 1,200 random walks); a shot hitting the ground on a slope or bank makes exactly such craters. Its contour count (0x513390) also loops forever when a crater outline runs along a terrain polygon's edge and touches it at a corner. Both fixed in the port |
| Pressing Esc at a resolution above 640x480 crashes; Options from the pause menu crashes above ~1000 lines; 1152x864 broken | VOGONS (teleguy's resolution patch), PCGamingWiki widescreen fix | Partly explained (menus.md, Resolution): the pause screen makes the option screens at the mission's size, and their still background is drawn with that size as the source rectangle of a 1280x960 picture, so above 960 lines (exactly 1280x1024 and 1600x1200) the draw reads past it. The original's switch to 640x480 before the first frame should clip it, so the crash is likely in a draw before the switch or in the switch's own screen grab (zVideo, not ported). The port cuts every source rectangle at its image (FIX (B), fixes.md). Esc above 640x480: the pause screen is ported now (menus.md section 11); it opens at the mission's size with no mode switch, over a still of that size, and has no size-dependent code of its own, so the crash is not in its constructor or presses; its draw at that size is not yet traced |
| Three resolutions in the menu plus three hidden (1152x864, 1280x1024, 1600x1200) set only in the registry | VOGONS | Confirmed (settings.md): InGameVMode, the mode a mission starts in, is saved and read as any number, and the mode switch 0x40d810 knows 8, 9, 10 as 1152x864, 1280x1024, 1600x1200; the VMode the menus use is never saved |
| Internal aspect ratio fixed at 4:3 | PCGamingWiki | Projection is ported (`render-matrix.md`); widescreen would be a FIX (B) candidate |
| DDrawCompat: the picture sometimes freezes while the game runs | VOGONS | A wrapper issue, not the game's; the port does not use DirectDraw |
| A famous targeting exploit used by speedrunners. Likeliest: an order to the lancemates ("attack my target", "defend") given with the reticle over an enemy breaks that enemy's AI, which stops fighting back, freezes or spins | Owen, from an AI search summary (unverified); the SDA run's notes back it: "the game converts that point of the map into a target ... which the enemy identifies as being hostile" | Open, AI area: check the squad orders (0x4d6c90 and the order commands) and how a point becomes a target (`ai.md`) when the AI resumes. Not the reticle lock itself: keypad Ctrl-0 freezing the reticle over a part (legs, hips) is a feature (readme: Toggle Torso Mode) |
| Zoom and reticle targeting as exploits (playtest #7's watch, 2026-10-21) | the port, not a report | Checked with the HUD keys (hud.md section 19): Z, keypad 0 and Q target only what the sensors already list (the contacts), so they reach nothing the target keys could not; the zoom costs torso speed (30%) while open, locked or held. Two oddities: Q targets allies (Z skips them), and Z or Q over an object the sensors do not list drops the current target. Whether "attack my target" (F6) with an ally targeted turns a lancemate on it is the AI area's (0x469930), and fits the speedrun report above as a lead |
| Infinite salvage: save at the moment the salvage prompt opens at a mission's end, reload, and the weapons, ammo and parts duplicate | the same AI summary (unverified) | Open; the save before the question was already found and fixed (FIX (bug), the world saved after "Replace existing game?", 3102324); check the salvage path (0x47ae10, campaign.md section 9) for a save that keeps the salvage store |
| Item duplication: the game checks the player has the items a loadout needs, not how many, so items duplicate (used for a whole Any% run) | Speed Demos Archive, MW3 Any% 0:30:44 (2022) | Found (mac 3, 2026-10-21, mech lab step 4): the store check 0x4735f0 compares each of a loadout's items alone with the store's count of that item (`count_like` 0x473510), never their sum. A loadout lists each weapon as its own item (one a mount), so two LRM-10s pass against a store holding one; taking the loadout (0x00433df0, 0x00472d40) removes two from one and the store's count stops at 0: the second is made from nothing. Reachable by choosing such a loadout in the mech lab (CONFIG_LIST, 0x00449c40) or by the briefing's fit (0x00408c30). Kept as the original (the port matches it: `Store::has_config`) unless Owen decides otherwise |
| A restarted mission keeps state from the last attempt: contact destroys buildings, an LRM salvo destroys several buildings at once, a lava explosion carries over | the same run's notes | Open; the port's mission unload and reset (mission-load.md) should be checked for state the original leaves behind |
